# weibo关注列表定律标签

在微博用户名旁显示自定义关注名单的匹配标签。查到该用户的可见关注列表包含名单博主时，显示 **“关注列表用户”**；鼠标悬停后展示匹配博主的名称、UID 和检查时间。

默认名单包含 **孤烟暮蝉（UID：2150758415）**，安装后可自行增删。标签仅表示查到了指定关注关系。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 点击 **[安装脚本](https://raw.githubusercontent.com/AndyCycle/weibo-following-law-label/main/dist/weibo-following-label.user.js)**，在油猴安装页确认安装。
3. 登录自己的微博并刷新页面。右下角出现“关注名单”后开始检查屏幕内的用户名。

若链接只展示源码，复制全部内容，在油猴中“添加新脚本”，替换原内容并保存。也可下载 `dist/install.html` 与同目录脚本文件，打开安装页复制脚本。

Chrome 提示缺少执行权限时，在 Tampermonkey 扩展详情中开启“允许用户脚本”。参见 [官方说明](https://www.tampermonkey.net/faq.php?locale=en&q=Q209)。使用时无需部署 Docker、启动本地服务器或安装 Node.js。

## 编辑名单

点击微博页面右下角 **“关注名单”**，每行填写一个 UID 或带数字 UID 的主页链接，后面可添加昵称：

```text
2150758415 孤烟暮蝉
```

或使用链接格式：

```text
https://weibo.com/u/2150758415 孤烟暮蝉
```

新增博主时另起一行，删除博主时删除对应行。点击“保存名单”后页面刷新。输入框需要 UID 或数字 UID 主页链接，单独填写昵称、自定义昵称地址不受支持。

名单按 UID 精确匹配，浮层昵称来自接口响应。名单与缓存保存在本机脚本管理器中，各用户之间不自动同步。分享自定义名单时，将名单文本一并发送给接收者。

## 标签与进度

- 查到任意一位名单博主即显示标签，并继续检查其余名单。
- 悬停、点击或用 Tab 聚焦标签可查看详情。
- 滚动新增内容自动识别，同一 UID 多处出现共用检查结果。
- 面板提供暂停、继续、清除缓存并重查，以及每位用户的进度。

没有显示标签时，请结合面板进度判断。关注不可见、接口过滤、分页截断、读取失败和扫描未完成均会限制检查结果。

| 策略 | 设置 |
| --- | --- |
| 处理范围 | 只为进入屏幕的用户名启动检查；页面隐藏时停止发起新关注列表请求 |
| 排队 | 单标签页一个队列，多位用户轮流逐页检查 |
| 请求间隔 | 相邻关注列表请求开始时间至少相隔 1.5 秒 |
| 单用户上限 | 250 页，达到上限时提示原因 |
| 每轮限额 | 300 次关注列表读取，点击继续检查增加下一轮额度 |
| 缓存 | 命中结果 6 小时，其他已结束结果 1 小时，每份名单最多 500 位用户 |
| 登录或访问校验 | 暂停队列，完成微博验证后点击继续 |

## 验证范围

已在可见的桌面 Chrome + Tampermonkey 中验证微博列表用户名旁的标签、同一作者多条微博的标签和鼠标进入后的名单浮层。

脚本配置覆盖 `weibo.com`、`www.weibo.com`、`s.weibo.com` 和 `m.weibo.cn`。个人主页顶部姓名、搜索页和移动页仍未逐一实测，不作为已验证兼容范围。可见范围由当前微博账号和微博接口决定。

本地自动检查 17 项通过，使用 jsdom 验证 DOM 行为，没有使用无头浏览器。见 [验证记录](VERIFICATION.md)。

## 数据与权限

运行时只向 `weibo.com` 读取关注列表及用于解析自定义主页 UID 的资料信息。名单和检查结果保存在脚本管理器本地存储中。没有向开发者服务器上传数据的功能，也不包含发布、关注、点赞或评论操作。

分发文件不包含登录 Cookie 或账号密码，每个使用者登录自己的微博。

## 更新

脚本声明了此 GitHub 仓库的更新和下载地址，可由油猴检查更新，也可重新点击安装链接更新。

旧版“微博关注名单标注”改名为“weibo关注列表定律标签”，保留原命名空间和存储键。若油猴将改名版识别为另一个脚本，请停用旧脚本，避免同时检查。需要沿用名单时，将旧面板中的名单复制到新脚本保存。

## 开发

需要 Node.js 22 或更高版本。在项目目录执行：

```sh
npm ci
npm test
npm run build
```

测试会自动构建并运行指定的两份测试文件。构建生成完整单文件脚本和安装页。开发时可执行 `npm run serve`，在 `http://127.0.0.1:8732/` 打开本机安装页。

可选的 `scripts/verify-live.mjs` 接收本机 Cookie 文件路径与样本 UID，执行只读接口验证；输出写入被 Git 忽略的 `verification/` 目录。此工具不参与浏览器脚本运行。
